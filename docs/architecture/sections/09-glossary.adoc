[[section-glossary]]
== Glossary

Project vocabulary, the coined domain terms especially. The media-model terms are the union types
resolution produces; their structure is in <<section-concepts>>.

=== Media model

Media:: The movies and shows Sammlarr tracks. No single `Media` type; a title is one of the union
types below.

MediaType:: `Movie`, `Show`, or `Unknown`.

`IMedia`:: A fully resolved title, `Movie` or `Show`. Every field is present.

`IPartialMedia`:: A title that has an identity but is still missing some fields (`PartialMovie`,
`PartialShow`). It is promoted to an `IMedia` once complete.

`IdentifiedMedia`:: The union of `IMedia` and `IPartialMedia`: a title matched to a library
row, so it carries a `MediaIdentity`. It may be fully or partially filled.

`UnmatchedMedia`:: External ids that could not be matched to any library row. It has externals
but no `MediaIdentity`.

`MediaLookup`:: The union of `IdentifiedMedia` and `UnmatchedMedia`: the result of resolving
external ids, matched or not. List building works over it.

`MediaIdentity`:: The identity of a matched title: Sammlarr's own `MediaId` plus the external
ids that resolve to it.

`MediaId`:: Sammlarr's internal GUID for a title. Never empty.

`IExternalMediaId`:: One provider's id for a title, with source provider, media type, and value.
Cases: `TmdbId`, `ImdbId`, `TvdbId`, `PlexId`, `MdblistId`.

Completeness:: Whether a partial title has all its fields. A complete partial is promoted to a
full `Movie` or `Show` (`MediaCompleteness.IsComplete`, `MissingFields`).

Freshness:: Whether a stored title is recent enough to skip a re-fetch: 7 days for a complete
title or a partial whose only gaps are `Tagline` and `BackdropUrl`, 1 hour for any other partial
(`MediaFreshness`).

CachedMedia:: The stored form of a title with the time it was fetched (an `IdentifiedMedia`
plus `FetchedAt`). Freshness reads `FetchedAt` to decide whether a re-fetch is due.

RatingSummary:: A title's aggregate rating: an average over the per-provider `MediaRating`
values, or `None` when it is unrated.

=== Resolution

Resolution:: Turning external references into the right library title, in two phases: _identity_
(Phase A, which library row the ids are) then _metadata_ (Phase B, filling in title, art and
ratings). The correctness-critical operation; see <<section-runtime-view>>.

Candidate:: One external id offered as input to resolution. Several candidates for the same title
are resolved together and merged into a single identity.

ResolutionHints:: Title, year and media type passed alongside the candidates to help a provider
match them to the right title, mainly the Plex title search.

Id converter:: An `IExternalIdConverter`, keyed by the target provider, that turns candidates
into a canonical identity. The Plex one searches by title and confirms each hit by id; the others
pass ids through.

Enricher:: An `IMetadataEnricher`, keyed by provider, that fills missing metadata fields in
Phase B. Sammlarr chains Plex then TMDB until the record is complete.

Coordinator:: The step that merges freshly resolved ids against existing library rows, so two
references to the same title never create two library ids.

Negative cache:: The in-memory cache of ids already known to be unmatched, kept for an hour and
checked before any provider call, so a repeated miss skips the providers (`IUnresolvedMediaCache`).

=== Curation

Feed:: A saved query over a provider list: the provider, the list `Identifier`, an add
strategy, an optional filter, sort, and limit, and a schedule.

Add strategy:: How a feed's results reconcile into the watchlist. `Append` adds them and leaves
them; `Mirror` keeps the items this feed added matching the feed, removing the ones that dropped
out of it. Mirror only ever touches its own slice, never manual, remote, or other feeds' items.
`FeedStrategy` is a union, so `Mirror` carries the data only it needs: an absence threshold, the
number of consecutive runs an item must be missing before it is removed.

Schedule (`SyncMode`):: When a feed runs: `Manual`, or `Scheduled` with a cron expression.
Only manual and preview runs exist today; see <<section-technical-risks>>.

Filter, Sort, Limit:: The query rules applied to a feed's source list (`QueryFilter`,
`QuerySort`, `QueryLimit`).

QueryVerdict:: What running a feed's rules over one candidate produces, carrying two independent
facts. `QueryOutcome` is purely the query verdict: `Qualified`, `Culled` (filtered out) or
`Truncated` (past the limit). `Enrollment` is what the user already did with the item:
`InWatchlist`, `InBlacklist`, `Owned` (this feed put it there). Questions like "will import" or
"at risk" are predicates over both, so nothing depends on the order the rules are checked in.
Unmatched candidates are reported separately as unresolved.

Watchlist:: The set of titles Sammlarr keeps in sync with Plex.

Provenance:: Where a watchlist item came from: `RemoteOrigin` (pulled from Plex),
`ManualOrigin` (search, browse, or feed preview), `FeedOrigin` (a feed put it there), or
`OrphanedOrigin` (its feed was later deleted).

Blacklist:: Titles excluded from curation so they never enter a list.

=== Providers and wiring

Provider:: An external service (TMDB, MDBList, Plex) or an id namespace (IMDb, TheTVDB),
modelled as a `MediaProvider` enum value.

Capability:: What a provider can do: `Search`, `Watchlist`, `Trending`, `Rating`, `Feed`,
`ApiKey`, or `Auth`. Declared per provider and used to generate the provider-subset enums.

Provider-subset enum:: A generated enum holding only the providers with a given capability,
such as `FeedProvider` or `WatchlistProvider`. See <<section-concepts>>.

Module:: An `IServiceModule`: a layer's or a provider's self-contained DI registration, added
from `Web`'s `Program.cs` via `AddModule<T>()`.

Keyed service:: A service resolved by an enum key, so a caller asks for, say, `IFeedService`
keyed to `FeedProvider.Mdblist`.

`ProviderConfig`:: The single global, admin-managed row of active provider selections (search,
rating, auth) plus the registration mode. Not per-user.

`ProviderUnavailableException`:: Raised when a provider's circuit breaker is open or a call times
out. Callers degrade on it (partial results) rather than fail a whole run.

=== Identity and access

Role:: `Admin` or `Member`. The first user to sign in becomes Admin; everyone after is a
Member. Admin manages providers, secrets, users and registration.

Registration mode:: `Open`, so anyone with a Plex account may join, or `Closed`, so new
sign-ins are rejected.

Secret:: An API key or a provider credential. Stored under data protection and redacted from
logs through `[Sensitive]`. See <<section-concepts>>.

`IUserOwned`:: A marker interface on entities that belong to a user. The `DbContext` gives each a
per-user query filter and stamps the owner on insert.

`IUserScope`:: Sets the ambient current user for a scope via `As(user)`, so background work (the
Wolverine handlers, the sync engine) runs under the right user's filters.

=== Sync and messaging

Sync:: Reconciling the local watchlist with Plex: pull remote changes in, push local changes
out.

Outbox:: The durable queue of pending watchlist pushes to Plex, drained by background messages
with retry and backoff. See <<section-runtime-view>>.

Delta:: The difference between the local and remote watchlist computed during a sync
(`WatchlistDelta`).

Notification:: A webhook or Pushover message emitted for a watchlist or sync event.

Channel:: How a notification is delivered: webhook or Pushover (`INotificationChannel`).

Target:: A configured notification destination, such as one webhook URL or Pushover account.

Subscription:: A rule binding an event type to a target and a template: who is told about what.

Template:: The Fluid template that renders a notification's title and body for a target.

=== Kernel types

These live in `Shared`, the kernel below `Domain`, and are used throughout.

`union`:: A closed set of case types, e.g. `MediaLookup` is `IdentifiedMedia` or
`UnmatchedMedia`. Matched by case directly.

`Optional<T>`:: A present-or-absent value (`Some` / `None`). Used instead of null for a missing
domain value.

`Result<T>`:: A success-or-error value (`Success<T>` / `Error`). Used instead of exceptions for
expected failures.

`ValueSet<T>`:: A set with value equality: two sets with the same elements are equal. Used for
genres and external ids.

NOTE: `sink` and `wantlist` are planned vocabulary from the media-sinks redesign, not built
yet. They are defined where that change is described, in <<section-technical-risks>>.
